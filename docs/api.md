# API

| | |
|---|---|
| **Status** | Day 4 |
| **Base URL (local)** | `http://localhost:8000` — interactive docs at `/docs` (disabled in `prod`) |
| **Source of truth** | OpenAPI generated by FastAPI from `src/customer_agent/api/` |

## Conventions

- JSON in UTF-8; customer-facing text is German.
- Every response carries an `x-request-id` header. Clients may send their own `x-request-id`
  (1–64 characters `A-Z a-z 0-9 . _ -`; anything else is replaced by a generated id); it is used
  in all log lines of that request.
- Authentication arrives on Day 5 (JWT bearer). Until then all requests are anonymous;
  `customer_id` is never accepted from the request body.

## `GET /health`

Liveness probe. `200 {"status": "ok", "version": "0.1.0"}`.

## `POST /v1/chat`

Sends one customer message. The server owns the transcript and the conversation state
(ADR-0005): the client sends only the new message and the `session_id` it received.

**Request**

```json
{"session_id": "f71d866745934838a39bb7e6d204fd65", "message": "Und in die Schweiz?"}
```

- Omit `session_id` to start a new conversation; use the returned id for every following turn.
- `message`: 1–10 000 characters; above 2 000 the reply asks the customer to shorten it.

**Response `200`**

```json
{
  "session_id": "f71d866745934838a39bb7e6d204fd65",
  "answer": "Der Versand in die Schweiz kostet 14,95 €, mit einer Lieferzeit von 4–7 Werktagen.",
  "behavior": "answer",
  "intent": "SHIPPING_INFO",
  "sources": ["info-shipping-international"],
  "request_id": "a1f3c09e2b4d"
}
```

| `behavior` | Meaning |
|---|---|
| `answer` | Grounded answer (`sources` lists the cited documents), or the greeting |
| `no_answer` | The knowledge base has no answer, or a dependency failed; the answer offers a human handoff |
| `clarify` | The agent needs more information (which order? what exactly?) |
| `refuse` | Out of scope, or order details requested without being logged in |
| `escalate` | Handed over to a human (complaints, explicit requests, order changes) |

`intent` is the router's classification (see [intent taxonomy](intent-taxonomy.md)) or `null`.

**Errors** — `404` unknown session (also for a session of another customer, from Day 5);
`409` another message of the same session was processed at the same time (retry);
`422` invalid request. Provider outages do **not** produce `5xx`; they degrade to
`behavior: "no_answer"`.

## `POST /v1/chat/stream`

Same request body; `404` for an unknown session (before the stream starts). Response is
`text/event-stream`:

```text
event: delta
data: {"text": "Der Versand in die Schweiz "}

event: delta
data: {"text": "kostet 14,95 €"}

event: final
data: {"session_id": "…", "answer": "…", "behavior": "answer", "intent": "SHIPPING_INFO", "sources": ["info-shipping-international"], "request_id": "…"}
```

- `delta` events contain display text (citation markers already removed).
- Exactly one `final` event ends the stream — or an `error` event
  (`{"status": 409, "detail": "…"}`) if a concurrent turn of the same session won.
- If the client disconnects, the turn still completes and is saved on the server. **Clients must replace the streamed text with
  `final.answer`**: an output guardrail may replace an answer after streaming started (for
  example when the model cited no source).

## Examples

```bash
# first turn: no session_id → the response contains a new one
curl -s localhost:8000/v1/chat -H 'content-type: application/json' \
  -d '{"message":"Was kostet der Versand nach Österreich?"}'

# follow-up in the same conversation, streamed
curl -sN localhost:8000/v1/chat/stream -H 'content-type: application/json' \
  -d '{"session_id":"<id from above>","message":"Und in die Schweiz?"}'
```
